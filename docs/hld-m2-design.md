## 3. 设计总原则（贯穿全文）

1. **尊重 CLAUDE.md 铁律**：稀缺推荐制无滑动、道具冻结、AED、三道闸、三层记忆、访谈三层分离、心理框架分层、L3+护栏同步、模型抽象层、禁过度设计。
2. **v1 量级禁过度设计**（BRD 9.4）：≤2000 注册、唯一峰值=周五送达。不引入 K8s/微服务/消息队列集群；单实例 + cron 调度。
3. **配置即资产**：Schema、问法库、模型路由表、定价均为**独立配置**（YAML/表），不硬编码进 prompt 或业务代码。
4. **i18n 自首行代码启用（BR-011）**：所有**新建/重建的前端**文案一律进语言文件（v1 只有 zh-CN 包）、Schema/枚举/代码全英文命名；不得把中文写死进组件。

## 4. 用户状态机（PRD 2.2）落库、鉴权与账号生命周期

### 4.1 状态落库（D1=A）
- `users.status` 单枚举列（S0–S7）+ **`user_state_transitions`** 事件表（from/to/reason/时间/触发源）留痕。
- 枚举与准入（PRD 2.2）：`S0访客 / S1已注册 / S2深访完成 / S3已验证候补 / S4付费 / S5配对中 / S6已毕业 / S7封禁`。跃迁 S1→S2→S3→S4 不可跳（三道闸）。
- 转移表价值：漏斗埋点（PRD 15 章 phone_verified/kyc_passed…）+ 决策回溯。
- 依据：PRD 2.2 / 5.4。

### 4.2 鉴权中间件
- 沿用 FastAPI **依赖注入**，新增 `require_state(min_state)`：解析 JWT → 取 user → 校验 `status` 达标；不达标返回**结构化"闸门未过"响应**，前端据此导流（补深访/去核验/去付费）。
- 例：查看推荐 ≥S4；深访接口 ≥S1；被推荐只需 S3。
- **单设备在线（BR-002）**：JWT 内嵌 `session_id`，users 存当前有效 session_id；新登录刷新 → 旧 token 失效 + 通知。登录页加"新设备登录将使其他设备下线"提示文案（E2 裁决）。

### 4.3 账号注销与封禁的冲突裁决（PRD 3.4 / BR-004 / A5）
- **S7 封禁用户不可自助注销**：仅保留申诉入口（注销会清数据，与"封禁需留证 + 防其借注销逃避拦截"冲突）。
- **普通注销（四道防线，PRD 3.4）** 到期执行级联删除（画像库/对话/**向量记忆库**/照片/KYC 结论），**保留最小合规审计记录**：
  - 脱敏哈希 + 注销时间 + 原因码 + KYC 事务 ID，**保留 12 个月**。
- **违规者（封禁）**：EID **单向哈希**进**永久拦截名单**（同一身份重新注册即拦，PRD 3.5 / BR-107），不受 12 个月清除影响。
- 依据：PRD 2.2(S7)/3.4/3.5 / BR-004/107。

## 5. BR-202 记忆体系重构（最高优先技术项，直接建在 Postgres 上）

### 5.1 三层 × 双轨模型
PRD 5.3.1 定义三层；技术上落为 **结构化画像库（事实/事件）+ 向量记忆库（语义/情感）双轨**（D2=A 应用层余弦，D7 同库 namespace）：

| 记忆层 | 内容 | 落地形态 | 更新来源 |
|---|---|---|---|
| 事实层 | 硬性字段、择偶条件+弹性系数、本地化维度、心理测评区块 | `user_profiles`(扩展)+`match_preferences`(扩展)+`user_psych_profile`(新) | 深访抽取 + 对话增量修正 |
| 事件层 | 婚恋旅程时间线：推荐/反馈、互聊摘要、约会记录 | `memory_events`(新，时间线表) | 系统事件自动写 + 对话提取 |
| 情感层 | 沟通风格、敏感点、情绪模式 | `user_comm_profile`(新) + 向量 `memory_vectors`(新) | 对话行为分析持续学习 |

> 向量：画像向量（现 `user_embeddings`）与记忆向量同表 `memory_vectors` 分 namespace(profile/emotion/narrative)（D7）；Postgres 列存 + 应用层余弦 Top-K（D2）。<2000 用户 O(n) 足够；pgvector 待规模需要再评估。

### 5.2 表设计骨架（字段级细节留 LLD）
- `user_psych_profile`：user_id、大五五维、依恋倾向、冲突风格、金钱观、价值观向量引用、各字段置信度。（PRD 5.3.6）
- `memory_events`：id、user_id、event_type、payload(JSONB)、occurred_at、source。（事件层）
- `user_comm_profile`：user_id、回避话题、兴奋话题、回答风格、情绪模式、更新时间。（Schema G + 情感层）
- `memory_vectors`：id、user_id、namespace、vector、source_text、created_at。（向量记忆库）
- `memory_pending_changes`：user_id、field、old/new、source、status。（PRD 5.4 待确认队列）

### 5.3 记忆读写管线
```
写：深访/对话结束 → 抽取器(旗舰/中档模型) → 结构化字段 upsert + 事件 append + 生成/更新向量
    对话中检出冲突/新增 → 写 memory_pending_changes → 小缘口头确认后落库并记变更历史(PRD 5.4)
读：小缘每轮 → 注入 = 系统prompt(人格) + 结构化画像摘要 + 向量检索 top-3(CLAUDE §4)
    重大变更(PRD 5.4 四类16项) → 触发匹配池重算标记
```
依据：BR-202 / PRD 5.3.1 / 5.4 / CLAUDE §3。

### 5.4 迁移路径（在 Postgres 上新建，废旧滚动摘要）
1. **在 Postgres 直接建**新三层表（M2 数据库即 Postgres，D3）。
2. **回填**：离线脚本把旧 `user_ai_memory.summary_text` + `ai_conversations` 历史 → 结构化字段 + 初始向量（M2 用户少，成本可忽略）。
3. **切换**：读写切新库；旧 `user_ai_memory` / `ai_memory_summary` 废弃（保留一版后删）。
- 说明：M2 真实用户极少，是重构记忆的最佳窗口（BRD 13.1 将 BR-202 列为唯一可并行技术项）。

## 6. 深访三层架构（PRD 5.3.5，架构铁律）

三层分离（配置与行为解耦）：
| 层 | 形态 | 存放 |
|---|---|---|
| 信息目标 Schema（强固化） | 24 必采字段(A/B/C/D 类)+级别+敏感度 | **独立 YAML**，禁入 prompt |
| 问法库（半固化） | 每字段 ≥2 问法 + 迂回策略 + 追问触发 | **配置化**，业务资产 |
| 系统 prompt（行为） | 仅人格 + 节奏 + 跳转 + 终止条件 | 随人格版本管理，极简 |

- **深访编排器**（应用层）：每轮 → 按 Schema 算字段缺口 → 选问法注入 → LLM 在人设约束下组织语言 → 抽取本轮信息 → 更新完成度/疲劳信号 → 决定继续/收尾。
- **双产物（BR-201）**：内部画像（落 §5 结构化库）+ 用户报告（先抽取落库**再**由旗舰模型生成，禁从原文直出）。
- **危机识别最小版（M2，挂在编排器上，PRD 5.5）**：关键词识别（自伤/抑郁表达）→ **固定话术（预置、不走生成）** + **UAE 本地专业资源卡片** + 暂停营销类主动触达。M3 升级为分级识别完整版。
- 依据：PRD 5.1–5.3.5 / 5.5 / BR-201/202 / CLAUDE §3。

## 7. 推荐流水线（T-3 → T0）任务调度设计（PRD 6.1，D4=B）

### 7.1 四阶段管线
| 时点 | 阶段 | 动作 | 产物 |
|---|---|---|---|
| T-3 周二 | 计算 | 候选过滤 → 打分（本地化硬约束 → 心理维度规则 → 语义向量相似度 → 综合分）；达阈值进草稿队列 | 候选"用户对"草稿 |
| T-2 周三 | 生成 | 每对生成推荐语（旗舰模型，缓存到 `match_insight_cache`）；具体性校验(引用画像≥2 处，连败 3 次转人工) | 推荐信文本 |
| T-1 周四 | 质检 | **S2 阶段人工 100% 终审**（A3）、S3 起 20% 抽样；性别比/供需检查 | 通过的推荐信 |
| T0 周五 20:00 | 送达 | 三通道送达（§8）；唯一峰值场景 | 用户收到推荐信 |

**T-3 候选过滤硬规则（显式补充）**：
- **画像速写未确认者不进候选**（PRD 6.5）：用户首次进候补池须预览确认画像速写；未确认前不出现在他人推荐中。
- **S5 活跃配对中暂停向其推荐新人**（PRD 5.4-⑫）：配对归档后自动恢复。
- 拉黑/熟人回避排除表命中者互不进候选（PRD 4.6/4.5）。

### 7.2 调度器（D4=B）
- **cron 触发独立脚本**：`python -m app.jobs.reco_stage --stage=T-3|T-2|T-1|T0`（OS cron / 任务计划）。与 Web 进程解耦，避免进程内线程多实例重复执行；连 Postgres（D3）规避 SQLite 并发写冲突。
- **幂等**：每阶段按 `批次ID(ISO 周)` 幂等，重复执行不重复送达；T0 送达失败进重试队列（§8）。
- **人工介入位**：T-1 质检队列（后台）——M2 阶段 S2 人工 100% 终审后才进 T0（A3）。
- 依据：PRD 6.1/6.4 / BR-301/307 / BRD 9.4 / CLAUDE §5。

## 8. 通知服务（新增·推荐送达与触达底座）

推荐信送达是产品的仪式感承诺（PRD 14.1），且 iOS PWA 的 Web Push 有平台限制，需**三通道 + 兜底**设计：

### 8.1 三通道
| 通道 | 定位 | 说明 |
|---|---|---|
| **站内信** | **必达底座** | 落库 `notifications` 表（替换现桩实现），用户进站必见；所有通知都先写站内 |
| **Web Push** | **主动触达主通道** | Service Worker + Web Push；iOS 需 16.4+ 且"添加到主屏幕"后才支持（E1） |
| **邮件** | **兜底通道** | Web Push 不可用/失败时（尤其 iOS 未装 PWA）对"周五推荐送达"等关键事件邮件兜底 |

### 8.2 送达可靠性
- **送达重试**：Web Push 失败进重试队列（指数退避）；连续失败降级邮件兜底。
- **到达率埋点**：`notification_sent / delivered / opened`（复用 event_logs），按通道统计到达率——直接支撑 PRD 14.1 送达准时性监控与 E1 风险量化。
- **偏好与频控**：为 M3 的 L3 主动触达（每周≤3 条、夜间不扰）预留频控字段；M2 先服务系统通知（推荐送达、审核结果、配对成功）。

### 8.3 M2 范围
- 必做：站内信底座（真实实现，废桩）+ 推荐送达/审核结果/配对成功三类系统通知 + Web Push 主通道 + 邮件兜底 + 到达率埋点。
- 依据：PRD 6.1(T0 送达)/14.1 / 现状 §5(通知桩) / E1。

## 9. Stripe 订阅 + EID KYC SDK 集成边界

### 9.1 Stripe（BR-501/503，PRD 8，A1）
**边界**（平台不碰卡号，全托管 Stripe）：
```
前端 → Stripe Checkout/Payment Element → Stripe 托管支付
Stripe → Webhook(签名校验, 按 event id 幂等) → 订阅服务 → 更新 subscriptions/orders + 状态机 S3↔S4
```
- **M2 实际开卖（A1）**：
  - **标准档** standard_monthly 149 / standard_quarterly 399；**早鸟 99 AED × 3**（Stripe 优惠券）。
  - **尊享试卖 5 席**（人工交付，非 L4；elite 全量 30 席目标留后）。
  - **高级档 M3 才开卖**：会员中心挂"即将开放"，**不收钱**。
- **冻结道具**（BR-503）：`super_like/boost/who_liked_me` 下架、购买接口返 **410**、前端入口移除；表与历史订单保留。
- **生命周期**（PRD 8.2）：升级按比例即时、降级/取消周期末无挽留、支付失败 3 次重试(1/3/5 天)→宽限 7 天→降回候补 S3。
- **付费墙位置（A4）**：**画像报告免费**（深访完成即得，转化钩子）；墙只设在"查看/回应推荐"（S3→S4）。
- **边界铁律**：卡号零留存；订阅状态以 Stripe 为准，本地表为投影。

### 9.2 EID KYC SDK（BR-107，PRD 4.1，A2）
**边界**（平台不碰证件图像，合规红线）：
```
前端 → KYC SDK 会话(EID NFC 优先/OCR 降级 → 活体自拍 → 服务商侧 活体↔芯片照 交叉比对)
服务商 → 平台仅收：结论(通过/失败/需人工)+姓名核验值+出生日期+性别+证件有效期+事务ID
平台：落 kyc_result 表 → 年龄/性别带入并锁定 → S2→S3
       照片：用户传3–9张 → AI预审 → 与活体照人脸比对 → 人工复审(SLA 48h)
```
- **核验节奏（A2）**：视频+人工核验**仅限免费种子期**；**首个付费用户之前 KYC SDK 必须就位**。
- **服务商（B1，暂缓）**：Uqudo / IDWise 类，集成边界一致；选型待商务确认。
- **边界铁律**：证件图像/活体视频**零留存**；仅存"结论+最小字段+事务 ID"；签 DPA（BRD 11.2）。
- 依据：BR-107/101/102 / PRD 4.1 / BRD 11.2 / CLAUDE §2。

## 10. 模型抽象层 + 计量（CLAUDE §4 / BR-209 / PRD 5.6）

### 10.1 模型抽象层（供应商可替换）
- **核心**：业务代码**只声明"任务 + 档位"**，绝不硬编码模型名。
```
route(task, tier) → 读【路由配置(任务→档位→provider→model)】→ provider adapter → 调用
任务档位(PRD 5.6.4)：深访/推荐分析=旗舰；军师复杂咨询=中档+缓存；日常陪伴/主动关怀=mini；记忆抽取/审核=mini+规则
```
- **必开 Prompt Caching**（PRD 5.6.5）；**记忆注入 top-3**（CLAUDE §4）；**产物缓存**按"用户对"（复用 `match_insight_cache`）。
- **provider adapter**：抽象 chat/embedding/STT/TTS 接口，换供应商只改配置（BRD 5.6.6）。

### 10.2 计量（BR-209，与功能同步）
- 每次调用记录 `user / scene / model / tokens(in/out) / cache_hit`（扩展 `user_token_usage` + `event_logs` 的 `ai_call` 事件，PRD 15）。
- **配额**：免费 20 轮/月；4o 升级次数按档配额。**全局预算熔断**：`global_ai_budget` 80% 告警、100% 全线降级 mini（PRD 5.6.5）。
- **成本看板**（后台，M2 即具备）：日/月成本、scene×model 分布、单用户 Top 消耗、预算进度条（PRD 11.1）。
- 成本目标：免费<1、标准<2、高级<8、尊享<30 AED/月；AI 成本占收入<5%。

### 10.3 后台 M2 必备（PRD 11.1）
照片人工复审队列（AI 预审+比对结论并列，SLA 倒计时）、举报处置台、推荐信质检队列、AI 成本看板。收件箱式视图（单人可运营）。
