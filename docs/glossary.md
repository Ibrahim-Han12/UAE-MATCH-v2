# 术语与编号约定（Glossary & Numbering Convention）

> UAE Match ｜ 日期：2026-08-22 ｜ 状态：**待批准**
> 本文件属**约定层**，只规定"同一个事实在本仓库里叫什么名字"，**不产生任何业务事实**。
> 业务事实的唯一权威是 `docs/权威规格/UAE_Match_BRD_v2.1.docx` 与 `UAE_Match_PRD_v1.1.docx`（**锚点层**）。
> 批准后按 §6 执行改名；执行前不改任何现有文件。

---

## 0. 为什么需要这一层

事实性冲突查锚点即可结案（例：BR-108 到底是什么 → BRD 第 494 行写"手机号验证：UAE 号码 OTP" → 结案）。

但**符号性冲突查锚点解不了，因为锚点自己重名**：

- BRD §8.2 定义 `S1/S2/S3` = 冷启动三阶段（验证期 / 人工+AI 混合期 / 产品化规模期）
- PRD §2.2 定义 `S1–S7` = 用户状态机（已注册 / 深访完成 / 已验证候补 …）
- PRD 第 313 行「T-1（周四）：质检——**S2 阶段**人工 100% 抽检，**S3 起**降至 20% 抽样」用的是冷启动义，出现在定义了状态机义的同一份文档里

两个事实都成立、都没写错，冲突只在于**共用了同一个符号**。本文件的唯一职责就是给重名的事实各发一张不同的名牌，并留下与锚点的对照关系。

**分层理由**：锚点层改动意味着商业含义变化，须由产品负责人升版；约定层改动只是换名字，不应惊动 BRD 版本号。混为一层会导致"改名要升 BRD"，结果无人改名、冲突持续累积。

## 1. 权威层级与引用纪律

```
① 锚点层  BRD v2.1 / PRD v1.1（docx）              业务与产品事实的唯一权威
   ↓
② 裁决层  docs/open-questions.md（DEC-xxx）        锚点未覆盖、由产品负责人裁定的
   ↓
③ 设计层  docs/hld-*.md、matching-algorithm-design.md   工程方案，不得与 ①② 冲突
   ↓
④ 代码层  代码与配置注释                            只准引用 ①②③，不准自造事实
```

**引用纪律（六条）**

| # | 规则 | 反例（现存） |
|---|---|---|
| R-1 | 代码注释引用锚点时必须写全出处段号：`PRD 5.6.4`、`BRD §8.2` | — |
| R-2 | 引用 HLD 必须写**文件名 + 章节**：`hld-m2-design.md §7` | `HLD §7`（4 份 HLD 都有 §7，15 处代码这么写） |

## 7. 基线文档处置（CLAUDE.md / AGENTS.md）

**现状**：两份除标题与一个词外完全相同（`diff` 仅 2 行差异），都含 F-1 的 BR-108 错误，都声称"你是唯一的开发协作者"。无同步机制。

**已确认的使用方式**：Claude Code 为主要开发者；Codex 于阶段完成后做只读复查。

| 文件 | 内容 | 理由 |
|---|---|---|
| `CLAUDE.md` | **基线正文**（全文） | Claude Code 会话启动时自动注入，零遗漏风险。主要开发者不应承担"多跳一步"的风险 |
| `AGENTS.md` | **3 行指针**：本项目基线见 `CLAUDE.md`，动手前先完整读它；复查纪律见本文件 §7 | Codex 自动读 AGENTS.md，由它跳一次。避免第三份文件与双份副本并存 |
| 代码注释 | 不再引用任何基线文件（规则 R-3） | 基线是 ①② 的派生摘要，不属可引用的权威层 |

> 本次会话实测：CLAUDE.md 被自动加载，AGENTS.md 未被加载——可作为"内容放 CLAUDE.md"的依据。

**双 agent 协作纪律**（写入基线，替换"唯一协作者"表述）：

1. **一份基线两边共读** —— 禁止在 AGENTS.md 内维护第二套规则。否则复查方会拿着旧规则书，把已改对的地方报成错。
2. **一次只有一个 agent 有写权限** —— Codex 只读复查、产出发现清单；改动由 Claude Code 执行。并行编辑产生互相覆盖的改动，仲裁成本落到唯一的人身上。
3. **交接前必须 commit** —— 未跟踪文件会让接手方丢失全部上下文。**已发生**：`AGENTS.md` 与 `docs/hld-dialogue-system.md` 至今未提交，本次会话只能从文件内容倒推其意图。
4. **复查范围限于可验证事实** —— 撞车编号、悬空引用、代码与文档一致性、锚点对账。**不用于**品味与产品判断（对话质感、交互模式选择），那类问题只会产出需要人来仲裁的第二份意见。

## 8. 新编号准入规则

新增任何编号族之前：

1. 查 §2 总表，确认符号未被占用（含大小写、含"字母+数字"全形态）。
2. 若新概念天然有好名字（如"意图层"），**优先不编号**——编号只用于有严格顺序或需要外键引用的场合。
3. 必须在 §2 登记：符号、含义、权威出处、落地形式、能否改。
4. 跨层引用一律遵守 §1 的六条纪律。
