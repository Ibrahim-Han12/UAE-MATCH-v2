# UAE Match · 匹配算法设计 v0.1

> 权威依据:BR-306 / PRD 6.1(T-3 计算)/ BRD 5.3.6(心理框架分层)/ interview_schema.yaml v0.2
> 消费方:推荐流水线 T-3 阶段(HLD §7);推荐语生成(BR-302,引用 score breakdown)
> 铁律:全部权重与阈值进 `config/matching_config.yaml`,业务代码零硬编码;
> 沟通语言层字段(F1 星座/F2 属相)匹配权重恒为零(5.3.6 分层原则,不可被任何调参突破)

---

## 0. 设计原则

1. **可解释优先于精巧**:每一个 pair 的得分必须能拆解到具体规则与字段,两个消费场景强制要求这一点——推荐语的具体性校验(引用双方画像 ≥2 处,BR-307)与推荐决策回溯(PRD 5.4 变更留痕)。因此 v1 采用**规则计分为主、语义向量为辅**,不用不可解释的端到端打分。
2. **宁缺毋滥**(PRD 6.4):阈值宁高勿低,推不出人走小缘弹性咨询,不为凑数降质。
3. **双向体验对等**:任何推荐对双方都必须是合格匹配,不存在"单方高分"的推荐。
4. **v1 量级不做工程优化**:≤2,000 用户全量两两计算(硬约束先过滤,进入计分的 pair 极少),周批离线跑,无需索引/召回架构——禁止过度设计(BRD 9.4)。

## 1. 总体流程(四阶段漏斗)

```
全量用户对 → Stage 0 资格过滤(状态与排除表)
           → Stage 1 硬约束过滤(双向布尔,淘汰 90%+)
           → Stage 2 规则计分(0–100,可解释)
           → Stage 3 语义调整(±,向量相似度)
           → pair_score = min(A→B, B→A)
           → 阈值裁决 → 候选草稿队列(T-2 生成推荐语)
```

## 2. Stage 0 资格过滤(状态层,布尔)

全部条件取自系统状态,任一不满足即出局:

| # | 条件 | 依据 |
|---|---|---|
| 0.1 | 双方 status ≥ S3(已验证候补) | 三道闸 |
| 0.2 | 画像速写已确认 | PRD 6.5(未确认不得出现在他人推荐中) |
| 0.3 | 双方均不处于 S5 活跃配对 | PRD 5.4-⑫(配对中暂停新推荐) |
| 0.4 | 不在互相排除表:拉黑(双向永久)、熟人回避、历史配对归档对 | PRD 4.6 / BR-105 |
| 0.5 | 历史已推荐对不重推;例外:双方任一发生重大变更重算且间隔 ≥8 周 | 防重复体验 |
| 0.6 | 性别互补(v1 假设:异性匹配) | **待确认项 Q1**(见 §9) |
| 0.7 | 非注销冷静期 / 非封禁 / 非毕业休眠 | PRD 3.4/2.2 |

## 3. Stage 1 硬约束过滤(画像层,双向布尔)

**弹性系数的过滤语义**(Schema C 类 `elasticity_value`):

| 弹性值 | 过滤行为 |
|---|---|
| hard | 严格过滤,不满足即出局 |
| negotiable | **不过滤**;允许在标称范围外扩展一档(年龄 ±2 岁、身高 ±3cm、收入/学历下探一档),进入计分但记减分(§4.5) |
| preference | 不过滤,仅计分 |

**逐项规则**(全部双向执行,A 满足 B 的条件 且 B 满足 A 的条件):

- **R1 年龄(C1)**:对方年龄落在 [min, max](hard)或扩展带(negotiable)。
- **R2 身高(C2)**:同上机制。
- **R3 学历/收入门槛(C3)**:对方 A5/A7 达到门槛;negotiable 允许下探一档。
- **R4 地域(C4 + B6)**:`same_emirate_only=true`(hard)时对方 A8.emirate 必须相同;跨酋长国场景校验双方 B6.cross_emirate;对方暂在国内场景校验 B6.partner_in_china_temp(单一事实源,Schema v0.2)。
- **R5 免谈项(C5,per-item)**:逐条对方事实映射校验——smoking→E5.smoking≠never 触发;heavy_drinking→E5.drinking=regularly;divorced→A3∈{divorced};has_children→B3(对方有孩事实,v1 由 A3+访谈叙事推断,置信度低时不触发过滤只降分);gambling→仅访谈叙事有明确信号时触发;long_distance→由 R4 覆盖。`elasticity_value=hard` 过滤,`negotiable` 转计分减分。
- **R6 去留规划(B1,硬约束级,BR-306)**:冲突矩阵——
  | | long_term_stay | return_within_years | depends_on_marriage | undecided |
  |---|---|---|---|---|
  | long_term_stay | ✅ | ❌ 过滤 | ✅ | ⚠️ 通过但计分降 |
  | return_within_years | ❌ | ✅(回国窗口差 ≤2 年) | ✅ | ⚠️ |
  | depends_on_marriage | ✅ | ✅ | ✅ | ✅ |
  | undecided | ⚠️ | ⚠️ | ✅ | ⚠️ |
- **R7 结婚时间线(B2)**:档位差 ≥3(within_1y × no_rush)→ 过滤;差 =2 → 通过但计分强降(§4.1)。依据 BRD 3.3"差距 >2 档提示预期错位",此处将"提示"落为分级处置。
- **R8 子女计划(B3)**:want=yes × want=no → 过滤;yes × open_to_discuss → 通过计分;对方有孩 × accept_partner_with_children=no → 过滤(事实置信度 stated 时)。
- **R9 宗教约束(E6/B5.religion_constraint)**:仅当任一方明示约束(如 same_faith_only)且对方事实明确冲突时过滤;字段缺失不过滤(E 类不阻塞)。

## 4. Stage 2 规则计分(0–100,五维加权)

> 权重初值如下,全部进配置;S2 人工终审期为校准期(§8)。

### 4.1 人生规划契合 — 30 分
- B1 组合:双 long_term_stay 或含 depends_on_marriage = 满分;含 undecided 按组合 -30%~-50%。
- B2 时间线:同档满分;差 1 档 -30%;差 2 档 -70%(强降权)。
- B3 子女:意愿与时间线同向满分;yes×open -40%。
- B4 养老:同向(如双 bring_to_uae)+加分项;冲突(bring_to_uae × return_to_care)-50%——该冲突是华人婚恋咨询高频雷区,权重必须足够疼。

### 4.2 心理兼容 — 25 分(BRD 5.3.6 落地处)
- **依恋组合矩阵(D1)**:
  | | secure | anxious | avoidant | mixed_unclear |
  |---|---|---|---|---|
  | secure | 100% | 85% | 85% | 90% |
  | anxious | — | 60% | **25%(强降权,不过滤)** | 70% |
  | avoidant | — | — | 55% | 70% |
  anxious×avoidant 为高危配对(BR-306),乘 25% 而非过滤——保留人工终审捞回的可能,但综合分基本无法达标,机制上"软过滤"。
- **冲突风格(D2)**:collaborative×any ≥85%;avoidant_withdraw×avoidant_withdraw = 40%(双回避=问题永不解决);competitive×competitive = 45%;accommodating×competitive = 55%(长期失衡模式)。
- **神经质(E1,存在时)**:双方 neuroticism 均 > 配置阈值(初值 0.7)→ 本维度整体 ×0.6(双高降权,BR-306);E1 缺失则跳过该项并下调本维度置信度(§4.6)。

### 4.3 价值观相似 — 20 分
D3 三子项(财务/事业/家务)逐项同向计分;D4 金钱观:同型满分,saver×spender_experience = 30%,其余组合 60–80%;E6 实践程度接近 +加分。**相似性加权,不做"互补"假设**——实证结论支持核心价值观相似优于互补(BRD 5.3.6)。

### 4.4 生活方式 — 15 分
作息(E3)同型 +;烟酒(E5)在对方非免谈前提下的接近度;社交半径(E7)相邻档兼容;兴趣标签(E8)交集数;居住距离(A8):同片区满分、同酋长国 80%、跨酋长国(双方 B6 允许前提下)50%。

### 4.5 条件满足度 — 10 分
双方对彼此 C 类条件的满足质量:全部 hard+标称范围内满足 = 满分;每一项走 negotiable 扩展带 -3 分(全局封顶 -6);preference 未满足项各 -2。**弹性扩展的代价在这里体现**——扩展带候选可以进来,但排序天然靠后。

### 4.6 缺失字段与置信度
- 维度内子项缺失:按已有子项归一化,不因缺失惩罚;
- 字段置信度 inferred(Schema G5):该子项得分 ×0.8;
- pair 整体置信度 = 各维度数据完备率加权,**随 breakdown 输出**,供 T-1 人工终审参考(低置信度 pair 优先人工看)。

## 5. Stage 3 语义调整(±5 分)

画像向量(深访全文向量)+ 叙事向量(F3/F4)的余弦相似度,映射为 **-0 ~ +5 分加分项**。v1 定位为 tiebreaker:向量质量未经验证前,不允许它主导排序(权重封顶 5%);S3 阶段用真实反馈数据(接受率 vs 语义分相关性)验证后再决定是否提权。

## 6. 综合分、阈值与冷启动

- `pair_score = min(score(A→B), score(B→A))` —— 取 min 而非均值,保证**双向体验对等**(0.9/0.5 的 pair 对后者是坏推荐)。
- **阈值(配置初值)**:稳态 `threshold=70`;65–70 为灰区,进 T-1 人工终审队列由人裁决(S2 阶段本来就是 100% 人工终审,灰区机制为 S3 自动化期预留)。
- **冷启动放宽(池 <200 人)**:threshold 降至 65,灰区下探至 55;**55 以下任何情况不推**——宁缺毋滥是产品承诺,不是运营参数。连续两周无合格推荐 → 触发小缘择偶弹性咨询(PRD 6.4),用池深数据支撑话术("你的 X 条件筛掉了池内 85% 的人")。
- **分配约束**:每人每周收到 ≤3(PRD);**同一用户同周最多出现在 3 个人的推荐信中**(防热门用户被轰炸、及其接受一个后其余配对希望落空)——**待确认项 Q3**。

## 7. 输出契约(score breakdown)

每个入选 pair 输出并落库:

```json
{
  "pair_id": "...", "batch_id": "2026-W33",
  "score": 78, "direction_scores": {"a_to_b": 81, "b_to_a": 78},
  "confidence": 0.86,
  "dimensions": {"life_plan": 27, "psych": 19, "values": 16, "lifestyle": 10, "condition_fit": 6},
  "semantic_bonus": 3,
  "triggered_rules": ["B1:both_long_term", "D1:secure_x_anxious", "C3:negotiable_extended(-3)"],
  "highlight_fields": ["B1", "E8:cooking", "B2"],
  "friction_point": "B2:timeline_gap_1"
}
```

- `highlight_fields` 供推荐语生成引用(BR-302/307 具体性校验的素材源);
- `friction_point` 供推荐信"一个诚实差异点"板块(PRD 6.2-④)——**算法直接为产品叙事供料**;
- 全量 breakdown 留存,满足 PRD 5.4 决策回溯。

## 8. 校准机制(S2 = 参数标定期)

S2 阶段 100% 人工终审(HLD §7)不只是质检,更是**算法校准数据源**:每次人工裁决与算法分的分歧(算法高分被人否 / 灰区被人捞回)记录为标定案例(pair_id + 人工理由码);每 4 周复盘一次,调整 matching_config.yaml 权重并升版。目标:S3 自动化开启前,人机分歧率 <15%。

## 9. 待产品负责人确认(3 项)

- **Q1 性别匹配假设**:v1 是否仅做异性匹配?(Schema A2 无性取向字段;若未来放开需加字段并过 UAE 内容合规评估——建议 v1 确认异性,Phase 2 议题)
- **Q2 阈值初值**:70/65(稳态/冷启动)是我基于五维满分结构的推导值,无实证——接受以此起步、S2 校准修正?
- **Q3 热门用户周曝光上限**:同周最多出现在几人的推荐中?我的建议 3(与个人每周接收上限对称)。

## 10. 明确不做(v1)

- ❌ 协同过滤/学习排序(数据量不支撑,且不可解释);
- ❌ 语义向量主导排序(§5,未验证前封顶 5%);
- ❌ 为性别比失衡在算法内做隐性补偿(供需问题走运营调控台,算法保持中立——在算法里藏运营逻辑是不可解释性的开端);
- ❌ 实时重算(重大变更打标记,统一 T-3 批处理;C 类状态变更的即时性由排除表/状态机保证,不需要重跑打分)。
