## 1. 说明

- **类别**：技术 / 合规 / 商业 / 运营 / 成本。
- **可能性 / 影响**：高 / 中 / 低。
- **等级**：由可能性 × 影响综合评定为 **高 / 中 / 低**（高影响 + 中及以上可能性通常判为高）。
- **责任角色**：以角色而非人名标注（PM=项目经理，BE=后端，FE=前端，DevOps=运维，法务=合规法务，运营）。
- **状态**：开放 / 缓解中 / 观察 / 已关闭。

## 3. 高等级风险应对重点

| 风险 | 关键动作 | 触发指标 / 预警 |
|---|---|---|
| R1 合规监管 | 发布前完成 PDPL 审查并整改，法律顾问确认婚恋类经营合规 | 审查未通过 / 出现监管问询 |

| R6 JWT/密钥 | 上线前强制轮换与配置校验，杜绝默认值入生产 | 配置扫描发现默认/明文密钥 |
| R7 数据库瓶颈 | 生产必须 PostgreSQL + pgvector，向量检索走索引 | 匹配接口延迟上升 / 并发报错 |

## 4. 风险管理机制

- **评审节奏**：每个里程碑（M1–M4）启动与收尾各评审一次风险登记册，更新可能性/影响/状态。
- **新增风险**：任何成员发现新风险可提报，PM 评级并指定责任角色。
- **关闭标准**：应对措施落地且触发指标连续无异常，方可置为「已关闭」。
- **联动**：本登记册与「产品 Backlog.md」的 P0 清单、「项目计划与里程碑.md」的关键路径联动，高等级风险须有对应 Backlog 项承接。
