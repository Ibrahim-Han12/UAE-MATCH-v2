# 00 · 项目计划与里程碑

> UAE Match ｜ 版本 v1.0.0 ｜ 更新 2026-07-04

---

## 1. 项目总目标与范围

### 1.1 总目标

将当前"功能骨架完整、可本地运行"的 v1.0，推进为**可对在阿联酋华人真实收费、合规运营的 Web 相亲产品**。核心是把三类缺口补齐：**商业化闭环（真实支付/会员权益）**、**真实运营态（去演示态、通知触达）**、**上线基座（安全、数据库、合规）**。

### 1.2 范围内（In Scope）

| 类别 | 内容 |
|---|---|
| 商业化 | 支付网关真实对接、订阅自动续费、会员权益前端落地、增值服务下单 |
| 真实态改造 | 去除前端演示态（10 秒自动过审 / VIP 前端开关 / mock 兜底 / 编辑资料打通）、通知系统落地 |
| 上线基座 | JWT 密钥治理、OpenAI Key 轮换、SQLite→PostgreSQL(pgvector)、Alembic 迁移、照片迁对象存储 |
| 合规 | UAE PDPL 数据保护落地、跨境数据说明、隐私政策/用户协议、数据导出与注销 |
| 运营 | 内容审核增强、后台数据看板、AI 成本监控 |

### 1.3 范围外（Out of Scope，本轮不做）

- 移动 App（iOS/Android）—— 列为远期形态目标（M4 之后）。
- 多语言（英语/阿语）—— 上线首版仍以中文为主，多语言列入增长期。
- 广告变现、社区动态、活动系统、消息增强（图片/语音/撤回）—— 三阶段及以后。

### M1 · 商业化闭环（第 1–6 周）

**目标**：让产品具备真实收款能力，会员权益从"前端开关"变为"服务端真实授权"，用户能被系统主动触达。这是从"能演示"到"能收钱"的关键跨越。

| 关键交付物 | 说明 |
|---|---|
| 支付网关真实对接 | 支付宝 / 微信 / 信用卡（Stripe）至少落地一条完整链路：下单→跳转→回调验签→订单/订阅落库 |
| 订阅自动续费 | `subscriptions.auto_renew` / `next_billing_date` 真实生效，到期扣费与降级 |
| 会员权益服务端授权 | VIP 判定由服务端订阅状态决定，移除前端 VIP 开关；额度/特权按 basic/premium 真实生效 |
| 通知系统落地 | 从桩实现补全为存储 + 站内通知 + Web Push（新匹配/新消息/被喜欢/订阅到期） |
| 照片流程打通 | 上传/审核/展示前端全流程可用，去除"10 秒自动过审"演示逻辑 |
| 编辑资料打通 | 前端编辑资料真实调用 `PUT /profile/me`，去除 mock 兜底 |

**退出标准**

- [ ] 至少一条真实支付链路端到端可用（含回调验签、失败重试、幂等）。
- [ ] 付费后 VIP 权益由服务端订阅状态授权，前端不再有硬编码 VIP 开关。
- [ ] 关键事件能产生真实通知并触达（站内至少可用）。
- [ ] 照片上传/审核/展示、编辑资料两条演示态链路全部转真实态。

---

### M2 · 增长与信任（第 7–12 周）

**目标**：在能收款的基础上，提升用户信任度与增长杠杆。婚恋产品的核心是"真实"，因此认证与内容治理优先于纯增长功能。

| 关键交付物 | 说明 |
|---|---|
| 用户认证增强 | 手机验证码注册/绑定；实名 / 学历认证徽章（可先人工审核） |
| 内容审核增强 | 关键词/正则方案叠加 AI 审核 + 举报人工复核闭环 |
| 高级筛选与搜索 | 作为会员特权（收入/学历/时间线/定居意愿等维度组合筛选） |
| 邀请与分享 | 邀请奖励机制，提升自然获客 |
| 数据分析看板 | DAU/MAU、付费转化、ARPU、续费率、AI 成本使用率上后台 |

**退出标准**

- [ ] 手机验证码链路可用；认证徽章在资料页可展示。
- [ ] 举报能进入"发现→复核→处置→记录"闭环。
- [ ] 会员高级筛选可用且受订阅授权约束。
- [ ] 后台看板能反映核心业务与成本指标。

---

### M3 · 上线准备（第 13–18 周）

**目标**：补齐上线基座——安全、合规、性能与可运维性，使产品达到"可对外正式运营"的门槛。此里程碑不新增用户功能，聚焦硬性上线条件。

| 关键交付物 | 说明 |
|---|---|
| 安全加固 | JWT 双密钥改为强随机并走环境变量；OpenAI Key 轮换；生产强制 HTTPS；API 限流与审计日志 |
| 数据库迁移 | SQLite → PostgreSQL；引入 Alembic 管理表结构；向量迁 pgvector + HNSW 索引 |
| 存储迁移 | 照片从本地磁盘迁对象存储（S3/OSS）+ CDN |
| 调度器改造 | 进程内守护线程改为独立调度 / 分布式锁，支持多实例部署 |
| 合规落地 | PDPL 合规审查；隐私政策与用户协议；数据导出/注销；跨境数据处理说明；婚恋类监管敏感性评估 |
| 部署与可观测 | Uvicorn+Gunicorn / 容器化 + Nginx；Redis 引入；错误追踪与指标监控 |

**退出标准**

- [ ] 无默认密钥/明文密钥进入生产；关键密钥完成轮换且走环境变量。
- [ ] 生产使用 PostgreSQL + pgvector，Alembic 可管理迁移。
- [ ] 照片走对象存储 + CDN；多实例部署调度不重复执行。
- [ ] PDPL 合规审查通过，隐私政策/用户协议上线，数据导出与注销可用。
- [ ] 生产环境全站 HTTPS，具备基础监控与告警。

---

### M4 · 发布与运营（第 19 周起）

**目标**：正式对外发布，进入以数据驱动的运营迭代节奏。

| 关键交付物 | 说明 |
|---|---|
| 灰度发布 | 小范围邀请制上线，验证支付/合规/性能真实表现 |
| 正式发布 | 面向 UAE 华人社群公开发布 |
| 运营机制 | 客服/风控/内容审核值守；成本与营收周报；用户反馈迭代 |
| 远期规划启动 | 多语言、移动 App、社区/活动等进入下一轮规划 |

**退出标准**

- [ ] 灰度期无 P0 支付/安全/合规事故。
- [ ] 关键运营指标（留存、转化、AI 成本预算率）可持续监测。
- [ ] 建立发布后迭代与值守机制。

## 4. 关键路径与依赖关系

### 4.1 依赖关系图（简）

```
M0(已完成)
  └─► 安全加固(JWT/Key)  ────────────┐
  └─► 支付网关对接 ──► 会员权益服务端授权 ──► 高级筛选(会员特权)
  └─► 通知系统落地 ──► 订阅到期/新匹配通知
  └─► 去演示态(照片/编辑资料/VIP开关)
                                     ▼
  数据库迁移(PG+pgvector) ──► 存储迁移 + 调度器改造 ──► 生产部署
                                     ▼
                              合规落地(PDPL) ──► M4 发布
```

### 4.2 关键路径（决定总工期的最长链）

**支付网关对接 → 会员权益服务端授权 → PostgreSQL/pgvector 迁移 → 合规落地(PDPL) → 灰度发布**

- **支付**是商业化前置，且会员权益授权强依赖真实订阅状态，不能仅靠前端开关。
- **数据库迁移**是性能与多实例部署的前置，向量 O(n) 检索在规模增长后必须换 pgvector。
- **合规（PDPL）**是发布的硬门槛，婚恋类 App 在 UAE 监管敏感，需预留审查与整改缓冲。

### 4.3 主要依赖说明

| 依赖项 | 被依赖方 | 风险 |
|---|---|---|
| 支付渠道商务/资质开通 | M1 全部支付功能 | 外部审批周期不可控，建议尽早启动申请 |
| PostgreSQL/pgvector 迁移 | 高级筛选性能、多实例部署 | 数据迁移与向量重建需停机窗口或双写方案 |
| 会员权益服务端授权 | 高级筛选、增值服务 | 需先移除前端 VIP 开关，否则授权模型不闭环 |
| PDPL 合规结论 | M4 正式发布 | 结论可能要求跨境数据/存储位置调整，影响架构 |
| OpenAI Key 轮换 | 上线安全基线 | 轮换需协调停机/灰度，避免线上调用中断 |

## 5. 假设与约束

### 5.1 假设

| # | 假设 |
|---|---|
| A1 | 目标市场首版聚焦在 UAE 的华人，界面以中文为主，暂不强制多语言。 |
| A2 | 至少能开通一条真实支付渠道（支付宝/微信面向华人用户，Stripe 面向信用卡）。 |
| A3 | v1.0 现有后端约 58 接口、20 张表结构基本稳定，改造以补齐而非重写为主。 |
| A4 | AI 成本可通过 gpt-4o-mini + 配额 + 全局预算控制在可接受区间（详见成本模型）。 |
| A5 | 首版承载规模为千级普通用户 + 百级 VIP 量级，SQLite 阶段仅限开发，生产用 PG。 |

### 5.2 约束

| 类别 | 约束 |
|---|---|
| 合规 | 必须满足 UAE PDPL；婚恋类社交在 UAE 监管敏感，内容与数据处理需保守合规。 |
| 数据跨境 | OpenAI 调用与云资源涉及跨境数据，需在隐私政策中披露并做合规评估。 |
| 成本 | 全局 AI 预算默认月度上限 $500，用量增长时须先扩预算或优化，不得无控超支。 |
| 安全 | 上线前禁止默认/明文密钥进入生产；生产强制 HTTPS。 |
| 技术债 | 无 Alembic、调度器进程内线程、照片本地磁盘等技术债须在 M3 前清偿。 |
| 资源 | 小团队，M1/M2 存在人力串行瓶颈，需按优先级（P0 优先）排布 Backlog。 |
