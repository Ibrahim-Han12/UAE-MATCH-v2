# 05 · 监控告警与回滚预案

> UAE Match ｜ 版本 v1.0.0 ｜ 更新 2026-07-04

本文定义 UAE Match 生产环境的监控指标、日志策略、告警规则、健康检查，以及故障时的回滚触发条件与流程。目标：**问题可发现、可定位、可快速恢复**。

---

## 1. 监控指标

### 1.1 系统层（基础资源）

| 指标 | 采集对象 | 关注点 |
|---|---|---|
| CPU 使用率 | API 节点 / DB / Redis | 持续高位=需扩容或有慢逻辑 |
| 内存使用率 | 各节点 | 内存泄漏、OOM |
| 磁盘使用率 | 数据库、日志盘、（迁移前）`backend/uploads/` | 磁盘满会导致写库/写日志失败 |
| 磁盘 IO / 网络 | DB、API | 向量检索、大量聊天时 IO 压力 |
| 进程存活 | Gunicorn worker、scheduler 节点 | worker 崩溃、调度线程停摆 |

### 1.2 应用层

| 指标 | 说明 |
|---|---|
| API 延迟（P50/P95/P99） | 按接口分组，重点：`/auth/login`、`/matches/suggestions`、`/match/recommend`、`/chats/{id}/messages` |
| 错误率 | 5xx 占比、4xx（401/403/429）趋势 |
| QPS / 吞吐 | 整体与热点接口 |
| WebSocket 连接数 | `/ws/chat/{id}` 当前活跃连接、断连率 |
| 数据库连接池 | 使用率、等待、慢查询（尤其向量检索） |
| 定时任务 | 缓存清理（每天 02:00 UTC）、VIP 关怀（周二/五 20:00 UTC）执行成功/耗时/是否重复 |

### 1.3 业务层

| 指标 | 说明 |
|---|---|
| 注册量 | 新增 `users` / 转化率（开始注册→完成注册） |
| 匹配活跃 | `match_actions`、互相匹配数、`match_pairs` 新增 |
| 聊天活跃 | `chat_messages` 量、被审核拦截量（`content_blocked` 事件） |
| 付费 | 下单数、支付成功率、订阅新增/续订、退款 |
| 举报/风控 | `user_reports` 新增、待处理数、限流触发（429）次数 |

### 1.4 AI 与成本

| 指标 | 说明 | 数据来源 |
|---|---|---|
| Token 消耗 | 每日/每月总 token | `user_token_usage`、`ai_conversations.tokens_used` |
| 预算使用率 | 月度已用 / 上限（默认 $500） | `global_ai_budget` |
| OpenAI 错误率 | 429（配额）、5xx、超时、回退次数 | openai_client 日志 |
| 模型回退率 | gpt-4o-mini → gpt-3.5 回退占比 | openai_client 日志 |
| 推荐配额触顶 | 用户推荐额度用尽（普通 2/月、VIP 10/月） | `user_recommendation_quota` |
| 成本告警 | 预算使用率阈值触发 | 见告警表 |

## 2. 日志策略

| 类别 | 内容 | 保留 |
|---|---|---|
| 访问日志 | Gunicorn access（`/var/log/uae-match/access.log`）：方法/路径/状态/耗时 | 30 天 |
| 错误日志 | Gunicorn error + 应用异常堆栈 | 90 天 |
| 事件日志（业务） | `event_logs` 表：登录、匹配、聊天、`content_blocked`、举报等 | 按合规要求（≥180 天） |
| AI 日志 | OpenAI 调用、token、错误、回退 | 90 天 |
| 审计日志 | 管理员操作（举报处理、预算修改 `global_ai_budget.modification_history`） | ≥1 年 |

原则：
- 集中采集（如 ELK/Loki 或云日志服务），可按 request-id / user-id 检索。
- **禁止记录**：明文密码、JWT、OpenAI Key、支付密钥、完整支付回调敏感字段。
- 生产 `DEBUG=false`，错误响应不暴露堆栈给客户端。

## 3. 告警规则与阈值

> 阈值为建议初值，上线后按实际基线调整。级别：P1=立即处理（呼叫值班）、P2=尽快处理、P3=观察。

| 指标 | 警告阈值（P2） | 严重阈值（P1） | 持续时间 |
|---|---|---|---|
| CPU 使用率 | >75% | >90% | 5 分钟 |
| 内存使用率 | >80% | >92% | 5 分钟 |
| 磁盘使用率 | >80% | >90% | 即时 |
| API 5xx 错误率 | >1% | >5% | 5 分钟 |
| API P95 延迟 | >800ms | >2s | 5 分钟 |
| 健康检查失败 | — | 连续 3 次失败 | 即时 |
| WebSocket 断连率 | >10% | >30% | 5 分钟 |
| DB 连接池使用率 | >80% | >95% | 5 分钟 |
| OpenAI 错误率 | >5% | >20% | 10 分钟 |
| AI 预算使用率 | >80% | >95%（临近 403 拒服） | 即时 |
| 支付成功率 | <95% | <85% | 15 分钟 |
| 401/403 激增 | 环比 ×3 | 环比 ×10 | 10 分钟 |
| 429 限流激增 | 环比 ×3 | — | 10 分钟 |
| 定时任务失败/重复 | 任一发生 | — | 即时 |

告警通道：P1 电话/IM 呼叫值班 + IM 群；P2 IM 群；P3 看板/日报。

## 4. 健康检查

- **端点**：`GET /api/v1/health`（无需鉴权），期望 `{"status":"ok"}`。
- **用途**：负载均衡/Nginx 存活探测、监控定时探测、K8s liveness/readiness。
- **探测建议**：每 15~30 秒一次，连续 3 次失败判定实例不健康并摘除/重启。
- **深度检查（建议增强）**：v1.0 的 health 为轻量检查。建议增加 readiness 探测数据库、Redis、OpenAI 可达性（可做浅检查/带缓存，避免探测本身放大故障与成本）。

```bash
# 手动验证
curl -s https://api.uae-match.com/api/v1/health
curl -s http://127.0.0.1:8000/api/v1/health
```

## 5. 回滚预案

### 5.1 回滚触发条件

出现以下任一情况，评估/执行回滚：
- 健康检查持续失败，重启无效；
- API 5xx 错误率 >5% 持续 10 分钟且无法快速定位；
- 核心功能不可用（登录 / 匹配 / 聊天 / 支付回调）；
- 数据出现错误写入或损坏风险；
- 安全事件（密钥泄露、越权、批量异常）；
- AI 成本失控（预算即将/已超且无法止损）。

> 决策人：技术负责人（不可用时由值班 SRE 代行）。回滚优先于长时间排障——**先恢复，再复盘**。

### 5.2 代码回滚（后端 / 基于 git tag）

前提：每次发布打 tag（如 `v1.0.0`）并保留上一稳定版镜像/tag。

```bash
cd /opt/uae-match
git fetch --tags
git checkout v1.0.0            # 上一稳定 tag
# 重装依赖（如有变更）并重启
source .venv/bin/activate && pip install -r backend/requirements.txt
sudo systemctl restart uae-match-api
# 容器化：回滚到上一镜像 tag 并重新部署
```

回滚后立即验证：`/api/v1/health` + 登录/匹配/聊天冒烟。

### 5.3 数据库回滚

**优先用 Alembic 版本回退**（若本次发布含 schema 变更）：

```bash
cd backend
alembic downgrade -1          # 回退一个迁移版本；或 alembic downgrade <revision>
```

**数据损坏则用备份恢复**（有数据丢失窗口，谨慎）：

```bash
# 停写：先停 API
sudo systemctl stop uae-match-api
# 恢复最近可用备份
pg_restore -c -U uae_app -h localhost -d uae_match /backup/uae_match_<最近>.dump
sudo systemctl start uae-match-api
```

> 注意：代码回滚若涉及不兼容 schema，须**代码与数据库版本匹配**。发布顺序建议向前兼容（先加列后用列），降低回滚耦合。破坏性 schema 变更前必须有即时备份。

### 5.4 前端回滚

- **Vercel/Netlify**：控制台一键回滚到上一次成功部署。
- **对象存储 + CDN**：将上一版 `dist/` 重新同步覆盖，并**刷新 CDN 缓存**使其生效。
- 保留每次构建产物（按版本归档），确保可快速切回。

### 5.5 局部止损（非全量回滚）

- AI 成本失控：临时下调 `global_ai_budget` 或关闭 `/match/recommend`、`/coach/match-insights`（超预算本就返回 403），保住核心交友功能。
- 定时任务异常：停用调度节点（`ENABLE_SCHEDULER=false` 重启该节点），不影响 API。
- 密钥泄露：立即轮换 `OPENAI_API_KEY` / JWT 密钥（注意改 JWT 密钥会使所有在线 token 失效，需公告）。
