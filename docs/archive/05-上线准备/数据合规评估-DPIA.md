# 数据保护影响评估（DPIA）

> UAE Match ｜ 版本 v1.0.0 ｜ 更新 2026-07-04

> ⚠️ **本文档为草案，正式发布前必须经阿联酋本地持牌法律顾问审核。** 本文旨在梳理产品数据处理活动、识别合规义务与风险，并列出上线前须完成的整改事项，不构成法律意见。文中对 UAE PDPL、中国 PIPL 及 GDPR 的引用为通行理解，最终解释与适用以主管机关及持牌律师意见为准。

## 1. 评估目的与范围

### 1.1 目的
UAE Match 是面向在阿联酋（UAE）生活的华人的 AI 智能相亲平台，收集与处理大量个人及**敏感个人数据**（婚恋意愿、宗教、照片、聊天内容、AI 对话记录等），并将部分数据传输至第三方（OpenAI、支付网关），且用户群体特性决定可能涉及 UAE 与中国之间的**跨境数据传输**。因此本 DPIA 用于：

- 系统梳理数据处理活动全景（收集—存储—处理—共享—跨境—销毁）；
- 对照 UAE 联邦第 45/2021 号法令（PDPL）及可能适用的中国《个人信息保护法》（PIPL），映射合规义务；
- 识别高风险处理环节并给出缓解措施；
- 落实数据主体权利机制；
- 形成上线前必须闭环的合规待办清单。

### 1.2 范围
- **产品形态**：先 Web、后移动 App。本评估覆盖当前 Web 后端（FastAPI + SQLAlchemy，20 张数据表）及既定的移动端扩展。
- **数据处理者**：UAE Match 运营主体（数据控制者），OpenAI、支付网关、云服务商（数据处理者/接收方）。
- **数据主体**：注册用户，仅限 18 周岁以上成年人。
- **地域**：数据主体主要为常驻 UAE 的华人；处理与存储发生地、跨境流向为本评估重点。

### 1.3 适用法规框架（初判）
| 法规 | 适用理由 | 关注重点 |
|---|---|---|
| **UAE PDPL**（Federal Decree-Law No. 45 of 2021） | 面向 UAE 境内用户、在 UAE 运营 | 合法性基础、同意、最小化、安全、数据主体权利、跨境传输 |
| **中国 PIPL** | 用户为在 UAE 的中国公民，且可能向中国境内回传/访问数据 | 单独同意、跨境传输机制、境内代表、敏感信息 |
| **GDPR（最佳实践参照）** | 作为国际通行的高标准基线 | DPIA、数据主体权利、Processor 协议、Privacy by Design |

> 注：UAE 各自贸区（如 DIFC、ADGM）另有独立数据保护法（DIFC DPL 2020、ADGM DPR 2021）。若运营主体注册于自贸区，须以该区法律为准——**须由本地律师确认适用法域**。

## 2. 数据清单（按 20 张表梳理）

以下按数据库真实表结构梳理所收集的个人数据，并标注敏感级别（🔴敏感 / 🟠一般个人 / ⚪非个人）。

### 2.1 账户与资料
| 表 | 字段 | 数据类型 | 敏感级别 |
|---|---|---|---|
| **users** | email, phone, hashed_password, is_active, is_admin, status | 身份识别、认证凭证 | 🟠（凭证经哈希，但邮箱/手机为直接标识符） |
| **user_profiles** | display_name, gender, birth_year, height_cm, nationality, current_country, current_city, occupation, company, education_level, bio, extended_info(兴趣/价值观/生活方式/性格) | 个人画像 | 🟠一般；`extended_info` 含价值观等可能触敏 |
| **user_photos** | file_path/url/name, file_size, mime_type, width, height, is_primary, is_verified, status, rejection_reason | 人脸生物图像 | 🔴 照片含可识别人脸，属敏感生物特征相关 |
| **match_preferences** | preferred_gender, min/max_age, min/max_height, **min_income_monthly_aed, religion, mbti, marriage_timeline, want_children, plan_settle_in_uae, plan_return_china**, education_level, notes | 择偶偏好 | 🔴 含**宗教信仰**、收入、婚育意愿——敏感 |

### 2.2 匹配与聊天
| 表 | 字段 | 敏感级别 |
|---|---|---|
| **match_actions** | actor_user_id, target_user_id, action_type(like/pass/super_like) | 🟠 情感/交往倾向 |
| **match_pairs** | user1_id, user2_id, status | 🟠 社交关系 |
| **chat_messages** | match_pair_id, sender_user_id, content(文本), is_read | 🔴 私密通信内容 |

### 2.3 安全与审计
| 表 | 字段 | 敏感级别 |
|---|---|---|
| **user_blocks** | blocker_id, blocked_id, reason | 🟠 |
| **user_reports** | reporter_id, reported_user_id, reported_message_id, category, description, status | 🔴 可能含指控性、涉及第三方的敏感描述 |
| **event_logs** | user_id, event_type, target_user_id/match_pair_id/message_id/report_id, meta(JSON) | 🟠 行为日志（风控/审计） |

### 2.4 支付与订阅
| 表 | 字段 | 敏感级别 |
|---|---|---|
| **orders** | order_no, product_type/id/name, amount, currency, payment_method, payment_status, payment_transaction_id, paid_at, callback_data | 🔴 财务/交易数据 |
| **subscriptions** | plan_type, status, started_at, expires_at, cancelled_at, order_id, auto_renew, next_billing_date | 🟠 消费状态 |

> 说明：支付卡号等完整支付凭证由支付网关处理，本平台仅存储订单号与交易回执（`callback_data`），须确认回执中不落地敏感支付凭证（PCI-DSS 考量）。

### 2.5 AI 相关
| 表 | 字段 | 敏感级别 |
|---|---|---|
| **ai_conversations** | role, content(用户与 AI 红娘"小缘"的完整对话), conversation_type, tokens_used, model, meta | 🔴 含用户自述、情感与偏好，且**内容会传至 OpenAI** |
| **ai_memory_summary** | summary_type, content（VIP 分层长期记忆） | 🔴 对个人的长期画像 |
| **user_ai_memory** | summary_text, token_count, last_updated_at（滚动摘要） | 🔴 长期画像 |
| **user_embeddings** | embedding_vector(1536维), source_text, dimension | 🔴 由个人资料生成的向量，`source_text` 含原文 |
| **match_insight_cache** | user_id, target_user_id, explanation, match_score_breakdown, opener_suggestions | 🟠 由 AI 生成的关系分析 |
| **user_token_usage** / **user_recommendation_quota** / **global_ai_budget** | 用量与预算 | ⚪ 运营数据（含 user_id 关联） |

**关键敏感数据结论**：本平台处理的敏感类别包括——① **宗教信仰**（match_preferences.religion）；② **人脸照片**（生物图像）；③ **私密通信**（聊天/AI 对话）；④ **收入/财务**（收入门槛、订单）；⑤ **婚育与人生规划意愿**。这些均需更高标准的合法性基础（通常为**明示/单独同意**）与安全保护。

**跨境节点识别（重点）**：

3. **→ 支付网关**：支付宝/微信为中国境内主体，交易数据可能流向中国。

## 4. 合规义务映射

### 4.1 UAE PDPL 要点
| 义务（PDPL 对应） | 本项目落地要求 | 现状/差距 |
|---|---|---|
| **合法性基础**（Art. 4） | 以**用户同意**为主，会员/支付以**合同履行**为基础 | 需在注册流程中显式获取同意并留痕 |
| **同意**（Art. 6） | 同意须自由、明确、可撤回；敏感数据须更明确同意 | 需分层同意（基础处理 / AI外发 / 跨境 / 敏感数据） |
| **数据最小化 & 目的限制**（Art. 5） | 仅收集匹配所必需字段；company/公司等非必要字段应可选 | 需复核 `extended_info`、company 的必要性 |
| **透明**（Art. 5） | 提供清晰隐私政策，说明 OpenAI 外发与跨境 | 隐私政策草案已配套（见另档） |
| **安全措施**（Art. 20） | 加密传输(HTTPS)、密码哈希、访问控制、日志 | JWT 默认密钥、OpenAI Key 曾明文——**须整改** |
| **数据主体权利**（Art. 13–19） | 访问/更正/删除/限制/可携/拒绝自动化决策 | 需提供导出与注销功能（见 §6） |
| **数据泄露通知**（Art. 9） | 泄露须及时通知主管机关及受影响主体 | 需建立事件响应流程 |
| **跨境传输**（Art. 22–23） | 仅可传至有充分保护的国家，或采取适当保障（合同条款、同意） | 向 OpenAI/中国的传输须有合法机制 |
| **DPO/记录** | 视规模指定数据保护官、维护处理记录（RoPA） | 建议指定合规负责人、维护本 DPIA 与处理记录 |

### 4.2 中国 PIPL 跨境要点（如适用）
> 触发前提：处理在 UAE 的**中国公民**个人信息，且存在向中国境内传输/访问，或运营主体被认定受 PIPL 域外效力约束。

| PIPL 义务 | 要求 |
|---|---|
| **单独同意**（第 39 条） | 向境外提供个人信息须取得**单独同意**，并告知境外接收方名称、联系方式、处理目的、方式、信息种类、行权方式 |
| **敏感个人信息**（第 28–29 条） | 宗教、生物识别（人脸）、行踪、金融账户等属敏感，须单独同意 + 必要性说明 |
| **出境合法机制**（第 38 条） | 三选一：① 通过国家网信部门安全评估；② 个人信息保护认证；③ 订立标准合同（SCC 备案） |
| **境内代表 / PIA** | 域外处理者须在中国境内设机构或指定代表；出境前须做个人信息保护影响评估并留存 3 年 |
| **未成年人** | 本平台仅限 18 岁以上，规避 14 岁以下须监护人同意的高风险场景 |

> ⚠️ PIPL 是否实际适用、以何种出境机制落地，须由熟悉中国数据合规的顾问结合运营主体注册地、团队所在地、数据流向确认。

## 5. 风险识别与缓解

| # | 风险场景 | 风险描述 | 严重度 | 缓解措施 |
|---|---|---|---|---|
| R1 | **跨境传输至 OpenAI（美国）** | 用户 bio、聊天、AI 对话、偏好文本外发境外，缺出境合法机制与用户单独同意 | 高 | ① 隐私政策明示 + 注册时单独勾选同意；② 与 OpenAI 签数据处理条款、启用不训练/零留存选项；③ 传前脱敏（去除直接标识符）；④ 评估 SCC/认证等出境机制 |
| R2 | **UAE↔中国 数据回流** | 运营/开发在中国访问生产库、备份或客服落中国，触发 PIPL 出境 | 高 | ① 明确数据存储与访问地图；② 生产数据访问最小化+审计；③ 如确有出境，落 PIPL 出境机制；④ 备份加密并限定存放地 |
| R3 | **敏感数据处理**（宗教/婚育/收入/照片） | 缺乏敏感数据专门同意与更高安全标准 | 高 | ① 敏感字段单独同意；② 加密静态存储；③ 最小化——评估宗教、收入是否必须；④ 照片访问需鉴权（见 R6） |
| R4 | **AI 处理与画像** | AI 红娘长期记忆、embedding 构成对个人的持续画像，涉自动化决策（匹配推荐） | 中高 | ① 告知自动化决策逻辑与影响；② 提供人工/规则匹配替代（strategy=rule 已存在）；③ 记忆可查看/可删除；④ AI 输出仅作参考并免责声明 |
| R5 | **聊天与举报内容** | 私密通信、举报描述含第三方信息，留存与访问权限风险 | 中 | ① 传输加密；② 管理员访问审计；③ 明确留存期；④ 举报内容仅限风控用途 |
| R6 | **照片文件访问控制** | `GET /photos/file/{filename}` 与 `GET /photos/{photo_id}` 当前**无需鉴权**，人脸图像可能被枚举/遍历访问 | 高 | ① 上线前加鉴权与授权校验；② 文件名随机化/签名 URL；③ 迁对象存储私有桶 + 短时签名 |
| R7 | **认证与密钥安全** | JWT 密钥为默认值、OpenAI Key 曾明文于 .env | 高 | ① 上线前更换为强随机密钥并入环境变量/密管；② 轮换 OpenAI Key；③ 定期轮换机制 |
| R8 | **支付数据** | callback_data 可能落地敏感支付信息；未接真实网关验签 | 中 | ① 回调验签；② 不落地完整卡号；③ 遵循网关 PCI 要求 |
| R9 | **内容审核局限** | 仅关键词/正则，漏判色情/诈骗，涉平台运营监管（UAE 对婚恋社交内容敏感） | 中 | ① 升级 AI 审核 + 人工复核；② 保留审核与处置记录；③ 明确社区规范（见用户协议） |
| R10 | **数据泄露** | SQLite 单文件、本地照片，泄露面集中 | 中 | ① 迁 PostgreSQL + 访问控制；② 静态加密；③ 备份加密；④ 泄露响应与通知流程 |

## 6. 数据主体权利落地

依据 PDPL Art.13–19（及 PIPL/GDPR 对应权利），须为用户提供以下可操作机制：

| 权利 | 落地方式 | 现状/待建 |
|---|---|---|
| **访问权** | 提供"我的数据"页/导出接口，涵盖 users/profiles/preferences/photos/chat/ai_conversations/orders | 现有 `/auth/me`、`/profile/me` 等仅部分；待建统一导出 |
| **更正权** | `PUT /profile/me`、`PUT /preferences/me` 已支持资料/偏好更正 | 已具备，需覆盖全部字段 |
| **删除权（被遗忘）** | 提供账号注销：删除或匿名化 users 及关联表、磁盘照片、embedding、AI 记忆 | **待建**：需级联删除/匿名化流程（保留法定留存项） |
| **数据可携权** | 以结构化通用格式（JSON/CSV）导出个人数据 | **待建** |
| **撤回同意** | 提供撤回 AI 外发/跨境/营销同意的开关，撤回后停止相应处理 | **待建** |
| **限制/拒绝自动化决策** | 允许改用规则匹配（strategy=rule）、关闭 AI 记忆 | 部分具备，需产品化开关 |
| **投诉权** | 提供隐私联系渠道，并告知可向 UAE 主管机关投诉 | 隐私政策中占位，需补实 |

## 7. 数据保留期与销毁

| 数据类别 | 建议保留期（草案，待律师确认） | 销毁/处理方式 |
|---|---|---|
| 账户与资料（users/profiles/preferences） | 账户存续期间；注销后 ≤30 天内删除或匿名化 | 硬删除或不可逆匿名化 |
| 照片 | 同上；注销后删除磁盘/对象存储文件 | 物理删除 |
| 聊天消息 | 账户存续期间；注销后删除（举报关联消息可延长至处置结束） | 删除/匿名化 |
| AI 对话与记忆（ai_conversations/memory/embeddings） | 账户存续期间；注销后删除 | 删除向量与摘要 |
| 举报/拉黑/事件日志 | 风控与法定需要期间（建议 6–24 个月），处置完成后清理 | 到期删除 |
| 订单/订阅 | 依财税法规（通常 5–7 年）保留 | 到期后删除 |
| 认证日志/安全审计 | 建议 6–12 个月 | 滚动删除 |

> 原则：超出目的即删除；因财税、法律义务需延长保留的，须有明确依据并最小化范围。

## 8. 上线前合规待办清单

- [ ] **法律审核**：由 UAE 本地持牌律师审核本 DPIA、隐私政策、用户协议，确认适用法域（含自贸区）。
- [ ] **PIPL 判定**：确认 PIPL 是否适用及出境机制（安全评估/认证/SCC），是否需境内代表。
- [ ] **同意机制**：注册流程实现分层同意（基础处理 / AI 外发 / 跨境 / 敏感数据），并留痕（时间、版本）。
- [ ] **OpenAI 处理协议**：签订数据处理条款，启用零数据留存/不用于训练；评估传前脱敏。
- [ ] **数据主体权利功能**：上线数据导出、账号注销（级联删除/匿名化）、撤回同意开关。
